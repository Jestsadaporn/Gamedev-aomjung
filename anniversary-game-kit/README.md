# Anniversary Game — ชุดทำงาน Designer / Developer / QA / Producer

เวอร์ชัน 1.0 | แผน ณ 6 พฤศจิกายน 2569 | เวลา Asia/Bangkok

เกมเว็บ 2D Pixel Art แบบเล่นคนเดียวสำหรับของขวัญครบรอบ 6 เดือน ตัวเอกเป็นนักศึกษาหญิงสุดเท่และหัวหน้าหน่วย มีมอเตอร์ไซค์สีชมพู ฉากได้แรงบันดาลใจจาก มจธ. พุทธบูชา และประชาอุทิศ เน้นเรื่องราว การแต่งตัว และการต่อสู้แอ็กชัน เล่นจบประมาณ 15 นาที รองรับคอมพิวเตอร์กับโทรศัพท์ ทุกคนที่มีลิงก์เปิดได้ ไม่ต้องสมัครสมาชิก

**กำหนดส่ง:** พร้อมภายใน 7 พ.ย. 2569 เพื่อเล่นจริง 8 พ.ย. 2569 ยังไม่ได้ตกลงเวลาส่งรายชั่วโมง ต้องให้กันกำหนดก่อนเริ่มแผนละเอียด หากใช้ชุดนี้หลังวันดังกล่าว ให้ทบทวนกำหนดกับกันและเริ่มส่วนที่ไม่ขึ้นกับกำหนดก่อนได้

> ชุดนี้เป็นเอกสารและ Prompt สำหรับทำงาน ยังไม่มีโค้ดเกม และยังไม่มีผลทดสอบเกมจริง งานใน Backlog เริ่มต้นเป็น Todo ทั้งหมด

## เริ่มใช้งาน

1. อ่าน `ROLES_REVIEW.md` และ `PRODUCT_BACKLOG.md` ก่อน
2. ใช้ `prompts/01_PRODUCT_OWNER_PRODUCER.md` ให้กันเลือกขอบเขตและข้อสมมติ
3. ส่ง README, Backlog และ `02_GAME_DESIGNER.md` ให้ Designer สร้างข้อกำหนดฉบับย่อ
4. ส่งเอกสารที่ตกลงแล้วกับ `03_GAME_DEVELOPER.md` ให้ Developer ทำเกมช่วงสั้นที่เล่นจบได้ก่อน แล้วเติมเนื้อหา
5. ให้ QA ใช้ `04_GAME_QA_TESTER.md` วางกรณีทดสอบตั้งแต่เริ่มงาน และตรวจ Build ที่ Developer ส่ง
6. QA รายงานหลักฐาน → Dev แก้ → QA ตรวจซ้ำ → Producer สรุปข้อจำกัด → กันตัดสินใจส่งจริง

เมื่อใช้ Prompt แยกห้องสนทนา ต้องแนบเอกสารปัจจุบันและรายงานส่งต่องานด้วย อย่าสมมติว่าอีกห้องเห็นบทสนทนาหรือไฟล์ทั้งหมด ทั้ง 4 เป็นบทบาทการทำงาน คนเดียวสวมหลายบทบาทได้ ไม่จำเป็นต้องเพิ่มคนหรือใช้หลาย Agent พร้อมกัน

## ขอบเขตเริ่มต้นที่เสนอให้ยืนยัน

มุมมองด้านบน (top-down) ฉากเล็กเชื่อม 2–3 พื้นที่ ศัตรู 1 ประเภท มีโจมตีและหลบ ชุดเต็มตัวอย่างน้อย 2 ชุดเปลี่ยนได้จริง มอเตอร์ไซค์ปรากฏในฉาก/เนื้อเรื่อง ยังไม่ทำระบบขับเต็มรูปแบบ เล่าเรื่องเป็น 3 ช่วงและมีฉากจบ เป็นข้อเสนอเพื่อคุมเวลา ไม่ใช่ข้อกำหนดที่ผู้ใช้ยืนยันทั้งหมดแล้ว

กรอบเวลาเล่นที่เสนอ: เรียนรู้/เปิดเรื่อง 2 นาที → สำรวจและแต่งตัว 4 นาที → ภารกิจ/ต่อสู้ 6 นาที → ฉากจบ 3 นาที ต้องวัดจากการเล่นจริง เป้าหมายประมาณ 12–18 นาทีสำหรับผู้เล่นใหม่ ไม่ใช่การรับประกัน 15 นาทีพอดี

มือถือเสนอเล่นแนวนอน มีข้อความแนะนำเมื่อถือแนวตั้ง ปุ่มเดิน/โจมตี/หลบกดพร้อมกันได้ คอมใช้ WASD/ลูกศรและปุ่มแอ็กชันที่ Designer ระบุ เลือกอย่างใดอย่างหนึ่งให้ชัดเจนก่อนพัฒนา ใช้กรอบข้อเสนอนี้ได้ระหว่างรอคำตอบ แต่ต้องติดป้ายว่า Proposed

## เทคโนโลยีและการส่งเกม

ค่าเริ่มต้น Phaser + JavaScript + Vite + Node.js บน Fedora, Git เก็บประวัติ ใช้ Editor ที่คุ้นเคย งานภาพใช้ LibreSprite/Tiled ได้ตามจำเป็น ไม่บังคับติดตั้งทั้งหมด ไม่ใช้ Backend, ฐานข้อมูล, Login, Multiplayer หรือ Docker ใน MVP โดยไม่มีเหตุผลจำเป็น

Dev ต้องตรวจเอกสารทางการและเวอร์ชันที่เข้ากันได้ก่อนติดตั้งจริง ชุดนี้ไม่ได้ยืนยันคำสั่งติดตั้งล่าสุดหรือราคา Hosting เลือก Static Hosting เพียงแห่งเดียวสำหรับรุ่นส่งจริง เช่น Cloudflare Pages หรือ itch.io เกมต้องไม่พึ่งเครื่อง Fedora เปิดทิ้งไว้

localStorage ถ้ามีจะอยู่เฉพาะ Browser/Origin ของอุปกรณ์นั้น ไม่ซิงก์ข้ามอุปกรณ์และอาจหายเมื่อล้างข้อมูล การเปลี่ยนโดเมนทดสอบไปโดเมนจริงไม่ย้ายเซฟให้เอง

## เกณฑ์พร้อมส่งร่วมกัน

- Build ระบุ commit/version และเปิดผ่าน URL จริงได้
- Must ใน Backlog ผ่านเกณฑ์ พร้อมหลักฐาน QA; ระบบที่ยังไม่ได้ตรวจห้ามนับว่าผ่าน
- เล่นต้นจนจบบนคอมและโทรศัพท์จริงเป้าหมายอย่างน้อยอย่างละ 1 เครื่อง ต้องระบุรุ่น/OS/Browser; อุปกรณ์อื่นเป็นขอบเขตที่ยังไม่ยืนยัน
- ไม่มี Critical/High ค้างในเส้นทางหลัก; สิ่งที่ยังไม่ได้ทดสอบและข้อจำกัดต้องระบุ
- ภาษาไทย/ปุ่ม/เสียง/การกลับจากสลับแอปไม่ขัดขวางการเล่น
- ข้อความฉากจบที่กันยืนยันและสิทธิ์ใช้ Asset ครบ ไม่มี Placeholder สำคัญหลงเหลือ
- มีไฟล์ Build ก่อนหน้าและวิธีย้อนกลับ Producer เสนอผลพร้อมส่ง กันเป็นผู้ตัดสินใจสุดท้าย

## ข้อมูลที่ยังต้องขอจากกัน

ชื่อ/คำเรียก/ข้อความฉากจบที่อนุญาตให้เผยแพร่, เวลาส่งวันที่ 7, รุ่นโทรศัพท์และ Browser หลัก, สเปก Fedora คร่าว ๆ, Asset ที่มีสิทธิ์ใช้ และการยืนยันข้อเสนอขอบเขต/แนวนอน ข้อมูลไม่ครบให้ใช้ข้อความสมมติและภาพชั่วคราวในรุ่นพัฒนาต่อได้

## แผนตามเวลาที่เหลือ

6 พ.ย.: Producer ล็อก Must → Designer ส่งข้อกำหนดขั้นต่ำ → Dev สร้างเส้นทางต้นจนจบแบบสั้น → QA เริ่มตรวจคอม/มือถือทันที

7 พ.ย.: เติมแต่งตัว/เรื่อง/Asset ที่อนุมัติ → ทดลองเล่นจับเวลา → ตรึงฟีเจอร์ → แก้บั๊ก → ตรวจ URL จริงและสำรอง Build เวลาตรึงฟีเจอร์เป็นจุดที่กันต้องตกลง ไม่ควรกำหนดโดยสมมติว่ามีเวลาทั้งวัน

8 พ.ย.: ตรวจลิงก์/หน้าเริ่มแบบสั้นก่อนส่ง หลีกเลี่ยงเพิ่มระบบใหม่ หากล่าช้าให้รายงานสิ่งที่เสร็จจริงและเสนอขอบเขตลดลงโดยไม่ซ่อนความเสี่ยง
